# IDEAMAN

毎日アイデアを提供してくれる。

行き詰まったときに「きっかけ」を与えてくれる存在。ユーザーの問いかけに答える
AI アシスタントではなく、**自発的にアイデアを生み出し、蓄積し、育っていく
システム**を目指している。

ボタンは「AI にリクエストを送る」ものではない。**すでに生まれていた考えを
覗きに行く窓**として作ってある。

## 動かす

```bash
python3 -m venv .venv && .venv/bin/pip install -e .
.venv/bin/uvicorn ideaman.app:app --reload
```

ブラウザで http://localhost:8000 を開き、**まず「いま取り組んでいること」に
テーマを登録してから**中央のボタンを押す。

API キーは不要。全機能がオフラインで動く。裏で考え続けさせるなら、別の
ターミナルで `ideaman worker` も回す。

## まずテーマを登録する

**ここを飛ばすと、出てくるのは宙に浮いた警句だけになる。** システムは
あなたが何に取り組んでいるかを知らないので、汎用の語同士をぶつけるしかない。

```bash
# いま作業しているディレクトリを読ませる（一番早い）
ideaman theme "IDEAMANを伸ばす" --scan .

# 手で入れることもできる
ideaman theme "IDEAMANを伸ばす" --add "通知,語彙,連鎖,評価,休眠,在庫"
ideaman theme                      # 一覧
```

`--scan` を付けると、**そこで実際に使われている語を読み取って材料にします**。
`--preview` を足せば、登録せずに何が採れるかだけ見られます。いらない語が
混ざったら `--drop` で外します（Web では材料をクリック）。1語でも的外れな
ものが残っていると、その語を含む案が出続けます。

```bash
ideaman theme "IDEAMANを伸ばす" --drop 場合,時間
```
手で登録するのが
面倒で放置されると、結局汎用の警句に戻るので、ここを自動にしてあります。

抽出は完全にオフライン（`ideaman/harvest.py`）。素朴な TF-IDF に、一つだけ
方針を足しています——**散文の語を識別子より優先する**。`conn` や `execute` は
言語の文法と慣習で決まる名前ですが、コメントや README の語はその人が自由に
選んだ語で、何を考えているかをそのまま表します。このリポジトリ自身を読ませると
`store` `conn` ではなく「連鎖」「休眠」「放浪」「衝突」が採れます。

Web の「いま取り組んでいること」（ディレクトリ欄に入れる）や、Claude からの
`ideaman_register_theme`（`scan_path` を渡す）でも同じことができる。

**材料**（`--add` に渡す語）は、あなた自身の言葉で書いた**部品の名前**にする。
文章ではなく単語。多いほど当たりが増える。

登録すると、衝突の片側があなたの材料に置き換わる:

```
登録前:  星座は、手紙のかたちをしている。
登録後:  通知の失敗したときの挙動を一切見えなくする。まず15分だけ試して捨てる。
```

出てくる文は2種類ある。どちらも語彙プールの `aspects`（順番・待ち時間・
例外の扱い…）と `probes`（15分だけ試して捨てる、5件だけ手で作ってみる…）
を使って、**いじる場所**と**最初の一歩**を必ず名指しする。

- **提案** — `{材料}の{側面}を{操作}。まず{試し方}。`
- **問い** — `{材料}の{側面}は、なぜ今の形なのか。`

これは SCAMPER / オズボーンのチェックリストと同じ原理で、推論力ではなく
**素材と操作の掛け合わせ**で具体性を出している。だから LLM が要らない。

## 稼動させる

このシステムは**溜まって育つ**ことが本体なので、置き場所の選び方がそのまま
性格を決める。要るのは3つ:

| 要るもの | なぜ |
| --- | --- |
| 永続ディスク | 溜めたアイデアと育った重みが消えないため |
| 常駐プロセス | 裏で考え続けるため（ワーカー） |
| 公開 HTTPS | Web を見るため。LINE を足すときにも必須 |

### 本番: Fly.io（推奨）

3つ全部揃う。`Dockerfile` と `fly.toml` を置いてあるので、そのまま載る。

```bash
fly launch --no-deploy          # 既存の fly.toml を使う
fly volumes create ideaman_data --size 1
fly deploy
```

Web とワーカーは**同じ1台に同居させる**（`IDEAMAN_EMBED_WORKER=1`）。
SQLite を共有する必要があるので、別マシンに分けてはいけない。

Discord Bot を動かすときも、同じディスクを見る必要があるので同じ machine で
動かす（`deliveries` テーブルをプロセス間キューとして使っているため）。

### デモ: Vercel

**触って感じを見るだけなら Vercel でも動く。** `vercel.json` と `api/index.py`
を置いてあり、push すれば自動でデプロイされる。

ただし Vercel はサーバーレスで**ファイルシステムが揮発する**:

- 溜めたアイデアも育った重みもコールドスタートで消える
- 常駐ワーカーが動かないので「裏で考え続ける」部分が無い

つまり **UI を触ってみる用**であって、本来の姿ではない。「毎日アイデアを
提供してくれる」を成立させるには上の永続ホスティングが要る。

### 手元だけで済ませる

ローカルで `uvicorn` と `ideaman worker` を回す。データは手元の
`ideaman.db` に残る。公開しないならこれで十分。

## しくみ

「AI の応答」ではなく「天啓」に感じさせるため、知識ベースではなく**衝突ベース**
で作っている。

1. `ideaman/data/lexicon.yaml` の語彙プール（概念・操作・制約・問いかけ・
   側面・試し方）から重み付きで語を引く
2. **分野タグが遠い組**を優先して選ぶ — 普段結びつかないものをぶつける
   (`engine/combinator.py`)。テーマが登録されていれば、片側は**あなたの材料**
   になる（`あなたの材料 × 遠い概念`）
3. テンプレートで日本語の一文にする (`data/templates.yaml`)
4. `ANTHROPIC_API_KEY` があれば Claude が文章を磨く（**任意**。キーが無い・
   失敗したときはテンプレート出力をそのまま使う）

生成されたアイデアは `unseen`（溜まっている考え）として SQLite に保存される。
ボタンを押すとまず在庫から1件取り出し、空のときだけその場で考える。起動時に
数件を先に作っておくので、たいてい「すでに考えてあったもの」が出てくる。

### 育つしくみ

👍 / 👎 を付けると、そのアイデアを構成していた語の重みが上下する（×1.15 /
×0.85、上限・下限つき）。次の抽選はその重みを読む。これが「蓄積していく」の実体。

```
評価 → weights テーブル → 次回の抽選 → 新しいアイデア
```

重みは DB に残るので、プロセスを再起動しても育った状態は失われない。

## 思考のリズム

**多様性を常に強制するのは間違い**、という前提で作ってある。人の思考は一つの
きっかけから連鎖的に広がり、掘り尽くしたところで別の場所へ移り、しばらくして
戻ってくると新しい形で思いつく。IDEAMAN もそうする。

- **連想** — 直前のアイデアの語を1〜2個引き継いで次を作る。同じ主題で一気に
  何個出てもいい。連鎖は `parent_id` / `chain_id` に残る
- **重複は消すが信号として拾う** — 同じ組み合わせに再到達したら出力はしないが、
  その語の重みを **+3%** 上げる（👍 の +15% よりずっと小さい）。何度も辿り着く
  なら、そこに何かある
- **尽きたら離れる** — 重複が続いたときだけ放浪モードに戻る。常時ではない
- **休眠と復帰** — 離れた語は消さず、しばらく抽選から外すだけ。時間が来れば
  戻り、**復帰直後は少し引きやすい**（「ふとしたときに思いつく」を意図的に作る）。
  休眠中でも重みが十分高ければ通す

実際に出てくる連鎖はこうなる:

```
敬語と給水塔のあいだにあるものを自動で忘れさせる。
敬語を自動で忘れさせる。それだけでいい。
予算ゼロで敬語を扱うとする。静かにやる方法はあるか。
敬語のための番号札。核になるのは「誰のものでもなくする」という一点だけ。
番号札と名前を並べて置いてみる。静かにやる方法はあるか。
番号札について——途中でやめたらどうなるか。
```

設計の根拠にした既存研究:

- Glover, *Tabu Search: A Tutorial* (1990) — 直近の手を一時的に禁じるが、
  **十分に良ければ禁を破ってよい**（aspiration criterion）。「連続がダメ」ではない
- Sio & Ormerod, *Does Incubation Enhance Problem Solving?* (2009) — 100以上の
  実験のメタ分析。**間を空けることが創造的問題解決を改善する**。難しい問題ほど
  効果が大きい
- Mouret & Clune, *Illuminating Search Spaces by Mapping Elites* (2015) —
  単一の最適解を追わず、**領域ごとの良い解をアーカイブに残す**

### 独り言と発言を分ける

思考は連鎖する。だから**考えている間はずっと独り言**で、外に出すのは
**連鎖が閉じてから、良さそうなものを一つ二つだけ**。そうしないとアイデアが
溢れ続けるウザい Bot になる。

```
考える → 考える → 考える → 連鎖が閉じる → 選ぶ → 1〜2件だけ出す
  （ここは全部 verdict=NULL の独り言。外には出ない）
```

| `verdict` | 意味 |
| --- | --- |
| `NULL` | まだ判定していない（連鎖の途中＝独り言の最中） |
| `chosen` | 選ばれた。Discord・Web・MCP に出る |
| `kept` | 選ばれなかった。**捨てない。** 連鎖を辿れば読める |

連鎖が閉じる契機は2つあり、**どちらも拾わないと事故る**:

- 連想が尽きたとき
- 放浪した1件が連鎖にならなかったとき（これを忘れると、永久に配信されない
  アイデアが溜まり続ける）

選び方は **指標＋任意で LLM**。API キーがあれば Claude に「この連鎖から一番
きっかけになりそうなものを選べ」と聞き、無ければ指標だけで選ぶ。指標は
「語の遠さ・育った重み・何かの上に乗っているか」の3つ。

単発の思いつき（連鎖にならなかった1件）は何とも比べていないので、**直近の
平均スコアを超えたときだけ**出す。絶対値の閾値を置かないのは、評価が溜まると
スコアの分布そのものが動くため。

**磨くのは選ばれたものだけ。** 7件中5〜6件は表に出ないので、出すと決まって
から LLM を呼ぶ（呼び出しが 1/4 以下になる）。

> **既知の限界**: 立ち上げ直後は評価がゼロなので、スコアは実質「語の遠さ」
> しか見ていない。200件で測ったところ**相異なるスコアは6種類しかなく**、
> 実態としては「2つの概念を衝突させる型」を「1つの概念だけの型」より
> 優先しているに近い。読むと選択自体は妥当だが、同じ型の中では区別できて
> いない。評価が溜まって重みが育つと意味を持ち始める、という性質のもの。

### リズムを見る

```bash
ideaman diversity
```

**重複率ゼロは正解ではない**（連想が効いていない証拠）。連鎖の長さが全部1なら、
それは思考ではなくただの乱数。見るのは「多様性が高いか」ではなく
「連鎖して、行き詰まって、離れて、戻ってくる」が起きているか。

500件生成した実測（リズムあり / なし）:

| | リズムあり | なし |
| --- | --- | --- |
| 連鎖の本数 | 144 | 500 |
| 連鎖の長さ（平均 / 最長） | 3.5 / 7 | 1.0 / 1 |
| モード | 連想 356 / 放浪 144 | 放浪 500 |
| 重複到達 | 34 | 0 |
| 休眠した語 | 125 | 0 |
| 語の被覆率 | 100% | 100% |

## 自発的に届く

裏で考え続けて、時間が来たら届ける。

```bash
ideaman worker              # 常駐して考え続ける
ideaman worker --once       # 1周だけ
ideaman idea                # ターミナルで一つ受け取る
ideaman chain 42            # 連鎖を辿る
ideaman theme "..." --scan .           # 読ませて材料を自動収集
ideaman theme "..." --add "通知,語彙"   # 手で足す
ideaman theme "..." --drop "場合"       # いらない語を外す
ideaman theme               # テーマ一覧
```

ワーカー・Web・Bot は**別プロセスで同じ DB を共有**する。どれが落ちても他は
生きる。プロセス間の受け渡しは `deliveries` テーブルが兼ねる（Redis 等は
持ち込まない）。

配信時刻は `IDEAMAN_SCHEDULE`（既定 `08:00,13:00,21:00`）。止まっていた間の分を
まとめて撃つことはしない。

### Discord

```bash
pip install -e ".[bot]"
export DISCORD_BOT_TOKEN=... DISCORD_CHANNEL_ID=...
python -m ideaman.bots.discord_bot
```

定期投稿が流れ、`/idea` でいつでも引き出せる。投稿には最初から 👍/👎 が付いて
いて、**押すとそのまま評価になる**（`/stock` で在庫と今のモードも見られる）。

投稿されるのは選ばれた1〜2件だけだが、**そこに至るまでの思考はスレッドに
入る**。Discord のスレッドは既定で畳まれているので、見たい人だけが開く。

### Claude から（MCP）

```bash
pip install -e ".[mcp]"
claude mcp add ideaman -- python -m ideaman.mcp_server
```

Claude に「何か良いアイデアない?」と聞くと、Claude 自身の思考に加えて
**IDEAMAN が溜めた考えを見に行く**。会話の中で「これ良いね」と言えば
`ideaman_rate_idea` が呼ばれてシステムが育つ。

| ツール | 用途 |
| --- | --- |
| `ideaman_receive_idea` | 溜まっている考えを一つ受け取る |
| `ideaman_browse_ideas` | 蓄積を見渡す（高評価順 / 語で絞る） |
| `ideaman_follow_chain` | 一つの発想がどう広がったか辿る |
| `ideaman_rate_idea` | 評価する（これで育つ） |
| `ideaman_register_theme` | いま取り組んでいることと材料を教える（**有益さの入口**） |
| `ideaman_list_themes` | 登録済みのテーマと材料を見る |
| `ideaman_stock_status` | 在庫と、いま何を考えているか（テーマ数も返る） |

会話の中でユーザーが取り組んでいる対象が分かったら、Claude が
`ideaman_register_theme` でその部品名を登録しておくと、以後の
`ideaman_receive_idea` がその課題の上に着地するようになる。

## LLM 仕上げ（任意）

```bash
.venv/bin/pip install -e ".[llm]"
export ANTHROPIC_API_KEY=...
```

有効にすると `source` が `llm` になる。無ければ `engine` のまま動き続ける。
LLM は**オプション**であって前提ではない。

## 設定

| 環境変数 | 既定 | 意味 |
| --- | --- | --- |
| `IDEAMAN_DB` | `ideaman.db` | SQLite のパス（全プロセスで共有する） |
| `IDEAMAN_STOCK` | `5` | 確保する在庫の数（0 で補充しない） |
| `IDEAMAN_SCHEDULE` | `08:00,13:00,21:00` | 配信時刻（ローカルタイム） |
| `IDEAMAN_EMBED_WORKER` | `0` | `1` で Web と同じプロセスでワーカーを回す（1台に載せるとき用） |
| `ANTHROPIC_API_KEY` | — | あれば LLM 仕上げが有効になる |
| `DISCORD_BOT_TOKEN` / `DISCORD_CHANNEL_ID` | — | Discord Bot 用 |

## API

| | |
| --- | --- |
| `POST /api/idea` | 溜まっている考えを1つ受け取る（空なら即時生成）。`?domain=` で分野指定 |
| `POST /api/idea/{id}/rate` | `{"score": 1｜0｜-1, "note": "..."}` |
| `GET /api/ideas` | 蓄積一覧（新しい順） |
| `GET /api/stock` | 在庫件数 |
| `GET /api/domains` | 分野タグの一覧 |
| `GET /api/themes` | テーマと材料の一覧 |
| `POST /api/themes` | `{"name", "note", "materials": [...], "scan": "パス"}`（同名なら材料を足す。`scan` でディレクトリから自動収集） |
| `POST /api/themes/{id}/active?active=` | そのテーマを休ませる / 再開する |
| `POST /api/themes/{id}/materials/drop` | `{"materials": ["場合"]}` で材料を外す |

## ロードマップ

1. **Phase 1（実装済み）** — ボタン → アイデア。生成エンジン・蓄積・評価
2. **Phase 2（実装済み）** — 常駐ワーカー・Discord・MCP・思考のリズム
3. Phase 2.5 — LINE（公開 HTTPS の置き場所を決めてから）
4. Phase 3 — 人の希望に沿わせる（分野・関心のプロファイル）
5. Phase 4（一部実装済み） — 閲覧許可を与えた文脈を材料にする。`--scan` で
   ディレクトリから語彙を収集するところまで。メモ・issue・チャットは未対応
6. Phase 5 — **自律思考ループ**。裏で Claude が過去のアイデアと評価を反芻し、
   自分で次の問いを立てて考え続ける

Phase 5 に向けて、以下を守っている:

- `service.generate_idea()` が生成の唯一の入口。Bot もワーカーもここを叩くだけ
- API は「在庫から取り出す」形。在庫の作られ方が賢くなっても API は変わらない
- `mood` / `parent_id` / `state` のカラムを先に用意（思考の連鎖を記録するため）
